# 基于哈夫曼编码的文件压缩程序学习与实现报告

## 一、项目概述

本项目使用 C 语言实现一个基于哈夫曼编码（Huffman Coding）的文件压缩与解压程序。

程序最终支持：

```bash
huffman -c input.txt output.huf
huffman -d output.huf output.txt
```

其中：

- `-c`：压缩文件
- `-d`：解压文件
- `input.txt`：原始文件
- `output.huf`：自定义哈夫曼压缩文件
- `output.txt`：解压后的文件

项目的核心目标不是单纯实现一个可以运行的压缩器，而是通过这个项目系统学习：

- 哈夫曼编码
- 贪心算法
- 二叉树
- 最小堆
- 优先队列
- 递归
- C语言指针
- 二级指针
- 动态内存
- 文件 I/O
- 二进制文件
- bit 级别读写
- 自定义文件格式
- 模块化程序设计
- 内存管理

# 三、哈夫曼编码的基本思想

哈夫曼编码是一种经典的无损压缩算法。

核心思想是：

> 出现频率越高的字符，使用越短的编码；出现频率越低的字符，可以使用较长的编码。

例如：

```text
A：出现 8 次
B：出现 4 次
C：出现 3 次
D：出现 2 次
E：出现 1 次
```

哈夫曼算法会优先把频率最低的两个节点合并。

例如：

```text
E(1) + D(2) = 3
```

然后：

```text
C(3) + 3 = 6
```

继续合并，最终形成一棵二叉树。

树的路径决定编码：

```text
左边 = 0
右边 = 1
```

例如：

```text
        ROOT
       /    \
      A      *
            / \
           B   *
              / \
             C   D
```

那么可以得到：

```text
A → 0
B → 10
C → 110
D → 111
```

高频字符位于较浅的位置，因此编码较短。

---

# 四、为什么哈夫曼编码可以进行无损解码

哈夫曼编码具有一个非常重要的性质：

> 前缀码（Prefix Code）。

即任何一个字符的编码都不会成为另一个字符编码的前缀。

例如：

```text
A → 0
B → 10
C → 110
D → 111
```

不会出现：

```text
A → 0
B → 01
```

这种情况。

因此：

```text
010111...
```

可以唯一地按照哈夫曼树进行解析。

解码过程：

```text
从根节点开始
      ↓
读取一个 bit
      ↓
0 → 左子树
1 → 右子树
      ↓
到达叶子节点
      ↓
得到一个字符
      ↓
重新回到根节点
```

这就是 `decodeData()` 的核心逻辑。

# 五、哈夫曼树的数据结构

项目使用：

```c
typedef struct HuffmanNode {

    unsigned char data;

    uint64_t frequency;

    struct HuffmanNode *left;

    struct HuffmanNode *right;

} HuffmanNode;
```

其中：

### 1. `data`

```c
unsigned char data;
```

因为一个文件最基本的处理单位是 byte。

一个 byte 有：

```text
8 bit
```

因此可以表示：

```text
0 ~ 255
```

总共 256 种可能。

---

### 2. `frequency`

```c
uint64_t frequency;
```

表示该字符出现了多少次。

使用 `uint64_t` 是为了避免处理较大文件时频率计数溢出。

---

### 3. `left` 和 `right`

```c
HuffmanNode *left;
HuffmanNode *right;
```

分别指向左右子树。

这也是 C 语言中结构体自引用指针的典型应用。

---

# 六、为什么使用 `left == NULL && right == NULL` 判断叶子

没有使用：

```c
data == 0
```

来判断叶子。

因为：

```text
0
```

本身就是一个合法的 byte。

例如二进制文件中完全可能存在：

```text
00
```

所以：

```c
if (root->left == NULL &&
    root->right == NULL)
```

才是正确的叶子节点判断方法。

---

# 七、频率统计

程序首先统计每一种 byte 出现的次数。

函数：

```c
void countFrequency(
    const unsigned char *data,
    size_t size,
    uint64_t frequency[256]
);
```

核心代码：

```c
for (int i = 0; i < 256; i++) {
    frequency[i] = 0;
}

for (size_t i = 0; i < size; i++) {
    frequency[data[i]]++;
}
```

因为：

```text
data[i]
```

本身就是：

```text
0 ~ 255
```

所以可以直接作为：

```text
frequency[]
```

的下标。

例如：

```text
data[i] = 65
```

对应：

```text
ASCII 'A'
```

因此：

```c
frequency[65]++;
```

# 八、最小堆与优先队列

构造哈夫曼树时，每次都需要找到：

> 当前频率最小的两个节点。

如果每次都遍历所有节点：

```text
找最小
找第二小
合并
重新找
……
```

效率较低。

因此项目引入了：

> 最小堆（Min Heap）。

数据结构：

```c
typedef struct {

    HuffmanNode *data[256];

    int size;

} MinHeap;
```

最小堆满足：

```text
父节点 ≤ 子节点
```

数组中的下标关系：

```text
parent = (i - 1) / 2

left = 2 * i + 1

right = 2 * i + 2
```

插入节点时：

```text
放到最后
   ↓
向上比较
   ↓
必要时交换
```

删除最小值时：

```text
取出根节点
   ↓
最后一个节点放到根
   ↓
向下调整
```

因此：

```text
插入：O(log n)

删除最小值：O(log n)
```

# 九、哈夫曼树的构造

核心算法：

```text
所有字符
   ↓
建立叶子节点
   ↓
加入最小堆
   ↓
取出最小的两个节点
   ↓
合并成父节点
   ↓
重新加入最小堆
   ↓
重复
   ↓
只剩一个节点
   ↓
根节点
```

伪代码：

```text
while 堆中节点数 > 1:

    left  = extractMin()
    right = extractMin()

    parent.frequency =
        left.frequency + right.frequency

    parent.left = left
    parent.right = right

    insert(parent)
```

这就是哈夫曼算法最核心的贪心过程。

---

# 十、为什么这是贪心算法

每一次都选择：

```text
当前频率最小的两个节点
```

进行合并。

这是局部最优选择。

最终得到全局最优的前缀编码树。

哈夫曼算法因此是经典的贪心算法案例。

# 十一、生成哈夫曼编码

建立树以后，通过 DFS 遍历树。

规定：

```text
左 = 0

右 = 1
```

例如：

```text
        ROOT
       /    \
      A      *
            / \
           B   C
```

遍历：

```text
ROOT → A
```

得到：

```text
0
```

遍历：

```text
ROOT → 右 → B
```

得到：

```text
10
```

遍历：

```text
ROOT → 右 → C
```

得到：

```text
11
```

程序使用：

```c
char codes[256][256];
```

表示：

```text
codes[字符][编码位置]
```

例如：

```text
codes['A'] = "0"
codes['B'] = "10"
codes['C'] = "11"
```

---

# 十二、为什么编码数组可以开成 `[256][256]`

第一维：

```text
256
```

对应：

```text
0 ~ 255
```

第二维：

```text
256
```

用于保存最长可能的哈夫曼编码以及：

```text
'\0'
```

字符串结束符。

对于最多 256 个叶子的二叉树，最深路径不会超过 255。

因此：

```c
char codes[256][256];
```

足够进行本项目的教学实现。

# 十三、字符串编码和真正的 bit 编码

最初我们可以把：

```text
A → 0
B → 10
C → 11
```

保存成字符串：

```text
"0"
"10"
"11"
```

但是如果直接写入文件：

```text
"01011"
```

计算机实际上保存的是字符：

```text
'0'
'1'
'0'
'1'
'1'
```

每一个字符占 1 byte。

也就是说：

```text
"01010101"
```

会占用：

```text
8 byte
```

而不是：

```text
1 byte
```

这就失去了压缩的意义。

因此必须进行：

> bit packing（位打包）。

# 十四、BitWriter

程序设计：

```c
typedef struct {

    FILE *file;

    unsigned char buffer;

    int bitCount;

} BitWriter;
```

例如连续写入：

```text
1
0
1
1
0
0
1
0
```

最终组成：

```text
10110010
```

刚好一个 byte。

然后：

```c
fputc(buffer, file);
```

写入文件。

# 十五、BitReader

解压的时候反过来：

```text
文件中的一个 byte
        ↓
10110010
        ↓
1
0
1
1
0
0
1
0
```

因此：

```c
readBit()
```

每次只返回：

```text
0
```

或者：

```text
1
```

如果文件已经结束：

```text
-1
```

# 十六、padding 问题

假设压缩数据只有：

```text
101
```

文件不能直接保存 3 bit。

所以补成：

```text
10100000
```

后面的：

```text
00000
```

就是 padding。

因此解压时不能简单地：

```text
一直读取到文件结束
```

否则可能把 padding 当成真正的数据。

项目使用：

```c
originalSize
```

记录原文件大小。

例如：

```text
原文件：

1000 byte
```

解压时：

```c
while (decodedSize < originalSize)
```

只要已经恢复：

```text
1000 byte
```

立即停止。

这样最后的 padding 就会被忽略。

# 十七、自定义 `.huf` 文件格式

本项目设计了自己的文件格式：

```text
┌────────────────────────────┐
│ magic = "HUF1"             │
├────────────────────────────┤
│ originalSize               │
├────────────────────────────┤
│ frequency[256]             │
├────────────────────────────┤
│ compressed bit data        │
└────────────────────────────┘
```

其中：

### `magic`

```text
HUF1
```

用于判断：

> 这个文件是不是我们程序生成的 Huffman 文件。

---

### `originalSize`

保存：

```text
原始文件大小
```

用于：

1. 处理 padding
2. 解压终止
3. 处理空文件

---

### `frequency[256]`

保存：

```text
每一种 byte 出现了多少次
```

解压时：

```text
frequency
    ↓
buildHuffmanTree()
    ↓
重新获得哈夫曼树
```

因此不需要直接保存整棵树。

# 十九、解压过程

`decompressFile()` 的工作流程：

```text

    │

    │

    │
```

这时候没有真正的：

# 二十一、内存管理

项目大量使用：

```c
malloc()
```

例如：

```c
HuffmanNode *node =
    malloc(sizeof(HuffmanNode));
```

因此必须对应：

```c
free(node);
```

哈夫曼树不能只：

```c
free(root);
```

因为：

```text
root
 ├── left
 │    ├── ...
 │    └── ...
 │
 └── right
      ├── ...
      └── ...
```

如果只释放 root：

```text
其他节点
```

都会泄漏。

因此使用递归：

```c
freeHuffmanTree(root);
```

顺序：

```text
左子树
   ↓
右子树
   ↓
当前节点
```

即后序遍历。

# 二十二、`readFile()` 中学习到的二级指针

函数：

```c
int readFile(
    const char *filename,
    unsigned char **data,
    size_t *fileSize
);
```

这里最重要的是：

```c
unsigned char **data
```

为什么需要二级指针？

因为函数需要修改调用者的：

```c
unsigned char *data
```

例如：

```c
unsigned char *data = NULL;

readFile(
    "input.txt",
    &data,
    &fileSize
);
```

这里：

```text

 ↓
保存内存地址
```

而：

```c
&data
```

是：

```text
data 变量自己的地址
```

因此函数才能：

```c
*data = buffer;
```

修改外部变量。

这是 C 语言中非常经典的：

> 输出参数 + 二级指针

模式。

# 二十四、程序的算法复杂度

假设文件中有：

```text
n
```

个不同的 byte。

由于 byte 最多只有 256 种：

```text
n ≤ 256
```

统计频率：

```text
O(N)
```

其中 `N` 是文件大小。

构造哈夫曼树：

```text
O(n log n)
```

生成编码：

```text
O(n)
```

压缩数据：

```text
O(N × 平均编码长度)
```

解压：

```text
O(压缩 bit 数)
```

由于：

```text
n ≤ 256
```

所以实际项目中哈夫曼树构造部分开销非常小。

# 二十五、目前程序的不足

虽然程序已经可以完成真正的无损压缩与解压，但它仍然是一个学习型实现。

## 1. 文件头比较大

当前：

```text
4 byte magic
+
8 byte originalSize
+
256 × 8 byte frequency
```

总计：

```text
2060 byte
```

所以如果原文件只有：

```text
100 byte
```

那么压缩后的文件可能反而更大。

这是正常现象。

因为：

> 压缩本身也需要保存元数据。

---

## 2. 整个文件一次性读取到内存

当前：

```c
readFile()
```

会：

```text
整个文件
    ↓
一次性 malloc
    ↓
全部读取到 RAM
```

所以对于非常大的文件并不理想。

更成熟的实现会采用：

```text
分块读取
```

甚至：

```text
两遍扫描文件
```

完成压缩。

---

## 3. 文件头中的整数存在平台兼容性问题

当前直接：

```c
fwrite(
    &header->originalSize,
    sizeof(header->originalSize),
    1,
    file
);
```

这依赖机器的字节序。

更完善的程序应该规定：

```text
little endian
```

或者：

```text
big endian
```

从而保证不同平台之间可以互相解压。

---

## 4. 哈夫曼编码表仍然使用字符串

当前：

```c
char codes[256][256];
```

例如：

```text
"010011"
```

这是非常适合学习的实现。

但真正追求效率时，可以直接保存：

```text
编码值
+
编码长度
```

例如：

```c
typedef struct {
    uint64_t code;
    int length;
} HuffmanCode;
```

这样就不需要使用：

```text
'0'
'1'
```

这样的字符串。

---

## 5. 还可以使用规范哈夫曼编码

更成熟的实现通常不会直接保存树，而是保存：

```text
code length
```

然后使用：

> Canonical Huffman Coding

重新生成编码。

这样文件头会明显缩小。

```text
                          │
                          ▼
                    无损恢复原文件
```

# 二十七、项目最终成果

目前我们已经实现了一个完整的基础版哈夫曼文件压缩器：

```text
原始文件
   ↓
统计频率
   ↓
最小堆
   ↓
哈夫曼树
   ↓
哈夫曼编码
   ↓
BitWriter
   ↓
自定义 .huf 文件
   ↓
BitReader
   ↓
哈夫曼树解码
   ↓
原始文件
```

最终验证标准不是：

> “解压出来看起来一样。”

而是：

```text
原文件
==
解压文件
```

必须做到：

> **逐字节完全一致。**

这就是无损压缩的核心要求。
